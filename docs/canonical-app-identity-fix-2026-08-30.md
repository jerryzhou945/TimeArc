# 应用重复项与默认图标修复（2026-08-30）

## 目标

同一应用的主进程和辅助进程只显示为一个应用，并使用一般桌面软件预期的主程序原生图标。微信的 `Weixin.exe` 与 `WeChatAppEx.exe` 是本次复现样例。

## 范围与改动

- 分类匹配仍返回具体规则 ID，设置页可以继续编辑自动生成的可执行文件变体。
- `ref` 通常只表示“来源于哪条出厂规则”，不能普遍作为聚合身份；本次仅把明确批准的
  微信多进程别名归并到 `app:wechat`。
- Opera、Brave、Vivaldi 等共享宽泛“其他浏览器”出厂规则的软件仍保留各自身份。
- 不修改历史数据库，不新增迁移；现有记录在读取聚合时自然归并。
- 代表路径策略继续优先选择主程序路径，因此微信使用 `Weixin.exe` 的 Windows 原生图标，而不是辅助窗口图标。

主要文件：`src/services/categorization/matcher.h`、`tests/db_smoke.cpp`。

## 验证

- 回归测试在修复前按预期失败，修复后通过。
- `python .harness/tools/build.py --track C`
- `ctest --test-dir build --output-on-failure`（6/6）
- 统计 JS 测试、桌面静态测试、运行进程和 Qt 日志扫描通过。

## 已知缺口

不重写历史记录是刻意选择。当前规范别名策略是显式白名单；新增其他多进程应用时，
需要带独立回归测试扩展策略。

## 回滚

回滚本修复对应的规范身份提交即可；没有数据库迁移或不可逆数据变化。
