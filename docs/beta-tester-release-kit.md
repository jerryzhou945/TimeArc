# TimeArc Beta 测试招募与视频发布包

日期：2026-08-20

## 60–90 秒视频脚本

1. **0–8 秒：问题** — “一天到底花在了哪些应用上？TimeArc 在本机替你记录。”
2. **8–25 秒：首页** — 打开 TimeArc，展示今日累计时间与应用卡；说明现在 Windows
   每次进入都会确认后台采集正在运行。
3. **25–42 秒：统计** — 切到统计与记忆湖，展示日/月趋势、应用分类和时间故事。
4. **42–58 秒：隐私** — 展示设置页；强调记录保存在本机，可关闭追踪，关闭后不再新增记录。
5. **58–75 秒：测试邀请** — “正在招募 Windows 和 macOS 测试者。请连续运行一天，
   告诉我漏记、误记、应用名称/图标和界面问题。”
6. **75–90 秒：行动** — 屏幕放下载入口、版本号和反馈模板；提醒 Windows 测试包未签名，
   macOS 包须完成签名/公证后再公开分发。

建议同时录制任务管理器中的 `TimeArc.exe` 与 `time-arc-service.exe`，再切回首页刷新，
用一段真实的“打开应用→产生记录”画面证明不是静态演示。

## 测试者检查清单

- 首次打开后 1 分钟内，今天是否出现当前使用的应用。
- 切换 3 个应用，每个停留至少 20 秒，名称、图标、时间是否合理。
- 静置超过设置的 idle 秒数后，活动时间是否停止增加；设为 0 后是否持续记录。
- Codex 前台运行一个超过 2 分钟的命令，期间不操作键鼠，确认时间仍增长；命令结束并继续静置超过 idle + 90 秒后应停止增长。
- Codex 只打开但不运行命令时，不应因为进程存在而持续计时。
- 退出再打开 TimeArc，今天的数据是否仍在并继续增加。
- 关闭“追踪正在运行的应用”并应用，确认不再新增；重新开启后恢复。
- 重启系统（仅自愿），检查“随系统登录启动 TimeArc”开关是否符合预期。

不要让测试者上传 `timearc_service.db`；它可能包含应用和窗口标题。优先收集截图、
操作步骤和脱敏后的状态输出。

## 发布门槛

- Windows：ZIP 解压启动、双进程、当天实时记录、关闭/恢复追踪、24 小时 soak。
- Windows 测试包为未签名便携 ZIP，下载页必须提示 SmartScreen、无自动更新和窗口标题本地记录。
- macOS：Mac 本机构建、Accessibility 权限流程、launchd 登录启动、签名、公证、DMG。
- 两端：版本号、隐私说明、已知问题、反馈入口必须与视频/下载页一致。
