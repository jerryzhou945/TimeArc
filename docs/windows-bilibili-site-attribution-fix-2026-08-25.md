# Windows B 站媒体归属修复（2026-08-25）

## 目标

修复 Chrome 播放 B 站视频时，视频页与 Windows 媒体接口都只提供视频标题、
不再包含 `bilibili` 后，时长被归入 Chrome 而 B 站记录不增长的问题。

## 范围与改动

- Windows 音频采样器短暂记住浏览器前台标题中明确出现的站点标记。
- 从 B 站页面进入无站点后缀的视频页时，把该标记写入稳定媒体身份；后续切换
  标签页不会拆分或丢失当前播放会话。
- 保留 Windows 媒体状态 `Playing`、前台与媒体区间并集、Discord 专用语音策略；
  不改数据库结构，也不改 Discord 的判断条件。
- Codex 回归夹具同步到当前桌面版 `26.818.8289.0` 与命令运行器
  `0.149.0-alpha.4.3`；生产逻辑仍按官方包内 `codex.exe` 子树聚合，不依赖版本名。

## 验证

- 失败测试先证明“明确 B 站页面 → 无标记视频标题”会丢失站点身份，修复后通过。
- Windows 前台、音频跟踪、媒体标题策略 3 组聚焦测试通过。
- 全部 6 个 CTest、Python 静态检查、4 个 Node 统计原型测试通过。
- 隔离配置下 Windows UI/服务生命周期烟测通过；新服务恢复后继续写入数据库。
- 真实数据库中当前 Codex 版本产生 68 秒前台区间、64 秒有效活动，验证官方
  工作进程的 CPU/I/O 变化可以在无持续键鼠输入时续租。

## 已知边界

Windows 不向普通桌面采样器暴露浏览器 URL。本修复依赖播放前 90 秒内曾采到
明确站点标题；从外部链接直接落到一个从未暴露站点名的视频页，仍只能归入浏览器。
后续若要求百分百站点准确率，需要可选浏览器扩展或仅域名级辅助通道。

## 回滚

回滚本次修复提交即可；磁盘契约与历史数据无需迁移。此前约 7 分钟已落盘记录仍
保留在 Chrome 分组，不对服务数据库做追溯改写。
