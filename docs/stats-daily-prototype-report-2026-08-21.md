# 桌面统计页每日应用时钟 Demo 报告

## 目标

基于当前桌面端 UI 重组统计信息层级：首页保持不动，统计页默认先回答“今天的时间落在了哪里”，再按需展开类别、时间流和应用排行。原型已经迁移进正式桌面 QML，并连接真实 `UsageStatManager` 数据；HTML/CSS/JS 版本继续作为交互和视觉对照稿。

## 本轮交付

- `docs/prototypes/timearc-stats-rework-v1.html`：桌面应用壳与统计页结构。
- `docs/prototypes/timearc-stats-rework-v1.css`：沿用 TimeArc 深色、湖青强调色和低噪声卡片语言。
- `docs/prototypes/timearc-stats-rework-v1.js`：每日应用时钟、周期切换、时间流、排行、全量应用库和详情交互。
- `tests/stats_prototype_behavior_test.js`：应用扇区、聚焦放大、中心信息和 SVG 输出回归测试。
- `tests/stats_prototype_app_library_test.js`：全量应用、累计时长、零使用项、搜索排序和图标输出回归测试。
- `qml/desktop/pages/StatsViewModel.js`：正式页面的纯数据变换层，合并本期与累计应用并生成 12 小时时钟扇区。
- `qml/desktop/pages/DesktopStatsPage.qml`：正式桌面统计页的每日应用钟、时间流、Top 概览和全量应用库。
- `tests/stats_view_model_test.js`：正式 QML view-model 的周期/累计合并、AM/PM 裁剪、排序和格式化测试。

## 关键设计

1. 采用当前桌面端 232px 侧栏、全幅暗色背景和宽屏内容区，不再切换为手机底部导航。
2. 每日视图顶部横向展示四项概览，主体以约 2:1 的应用钟表和分析栏组织，下方时间流与排行并排。
3. AM/PM 表盘直接放入具体应用图标；悬停或键盘聚焦时，对应扇区放大，其余扇区降噪，中心同步显示应用、类别、时间段和时长。
4. 点击应用锁定详情；时间流和应用排行可以反向定位表盘记录。
5. 周/月/年沿用相同桌面工作台，只保留一个主趋势、类别构成和应用排行。
6. Top 排行只负责快速概览；页面下方的「所有应用」以桌面表格完整列出本期时长、累计总时长、占比与最近记录，并支持搜索、排序和保留本期零使用的软件。
7. 不做效率评分或价值判断，仅展示可核对的时间事实；隐私开关可模糊应用名。

## 正式 QML 迁移

- 默认周期改为“日”，应用钟支持 AM/PM 切换、真实应用图标、扇区 hover 聚焦和中心详情。
- 日视图保留宽屏工作台结构：应用钟与占比分析、24 小时时间流与 Top 应用分别组成两组桌面双栏。
- Top 只做快速概览；完整应用库始终独立展示每个软件的本期时长、累计总时长和本期占比，并支持搜索、排序和显示本期未使用项。
- 周/月/年继续使用现有趋势、类别与排行，页面底部共享同一套完整应用库。

## 边界

- 未修改 C++、采集服务、数据库契约或首页；正式 QML 改动只消费既有只读统计 API。
- 数据来自浏览器内固定的隐私安全示例，不代表用户真实记录。
- Demo 使用内联 SVG 模拟应用图标；正式 QML 迁移时应复用现有 `AppIconImageProvider` 获取真实系统图标。
- Plan 未在本版建立独立页面；当前讨论中明确的统计重构先单独收敛。
- Windows 实时落盘、有效时长口径和通信会话识别属于独立 Track C，诊断见 `docs/windows-effective-time-diagnosis-2026-08-22.md`。

## 验证口径

- Node 行为测试验证每个应用独立成扇区、角度与时长一致、聚焦比例和降噪状态正确。
- 桌面布局回归测试验证 232px 侧栏、四列概览、两组宽屏双栏以及无手机底栏规则。
- Chrome 1440×1800 截图验证默认每日页、钟表图标和全量应用库；真实浏览器 DOM 验证周视图和周期数据。
- JavaScript 语法检查、仓库 diff 检查和 harness 检查作为交付门禁。
