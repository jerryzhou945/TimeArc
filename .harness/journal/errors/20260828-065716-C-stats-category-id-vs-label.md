## 1. What happened

monthMetrics/buildInsight/buildRecs index categorySums() (keyed by category IDs dev/office/notes/create/game/video) with English display labels cat['Games'],cat['Video'],cat['Creation'],cat['Notes'] and compare topCategory() to 'Development'/'Office'/'Games'. Never matches: Month 'Entertainment Share' and 'Creation Share' are permanently 0% and every recommendation falls to the generic default.

## 3. Root cause

- Immediate cause: categorySums()/topCategory() are keyed by the rule table's category **ids** (dev, office, notes, create, game, video), but monthMetrics(), buildInsight() and buildRecs() indexed and compared them with the English **display labels** ("Games", "Video", "Creation", "Notes", "Development", "Office"). No key ever matched.
- Underlying cause: Ids and labels are both plain strings and the labels read plausibly at the call site, so nothing about the code looked wrong; only the rule table shows they differ.
- Why the harness/checklists did not prevent it: Nothing checks that a string used as a category key is a real id. The failure is silent by construction: a miss yields 0, which renders as a legitimate-looking "0%".

## 4. Fix

- Files changed: qml/desktop/pages/DesktopStatsPage.qml
- Short description: All three call sites now use rule-table ids. Month view's Entertainment/Creation shares compute real percentages, and the recommendation branches can be reached.
- Commit: pending commit

One-off in kind, but the fix that prevents a repeat is the same one filed under stats-adapter-category-divergence: a single rowCategory() helper is now the page's only classifier, so there is one place to be wrong instead of six.
