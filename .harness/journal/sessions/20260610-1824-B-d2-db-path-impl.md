## Notes for the next agent

- The cross-process invariant rests on UI `usageConfigDir()` and service
  `timearc_get_usage_data_dir()` resolving the SAME `%LOCALAPPDATA%\TimeArc\usage`.
  In **test mode** the UI config dir is the test AppData (no service exists) — do
  not "fix" that to env-based or db_smoke will read the real user's usage dir.
- Migration REQUIRES collection stopped: the lock-probe (rename old DB to a
  sidecar) runs **before** the pointer switch, so a running service aborts cleanly
  with no split-brain. There is no in-process stop (B1) — the UI tells the user.
- Service-side `make_db_path` is verified by running the real binary (no service
  unit-test harness exists); keep that E2E in mind when changing the config read.
